# codex-status

一个基于 Electron、React 和 TypeScript 的 Codex 额度与任务状态工具。

通过系统托盘、悬浮胶囊和任务窗口查看额度与本机任务进度。Codex 轮次结束或中断后，可发送桌面通知，也可通过飞书群机器人通知 iPhone 和安卓手机。

## 友情社区

- [linux.do](https://linux.do/)

## 功能概览

- 悬浮胶囊窗口，常驻桌面顶层显示实际额度窗口，支持直接打开详情
- 支持剩余百分比 / 已使用百分比两种口径切换
- 官方 OAuth 可用时支持自动刷新和手动刷新
- 支持中英文界面
- 支持系统托盘菜单：显示/隐藏、刷新、设置、退出
- 读取官方额度接口，失败时仅展示同一账号最近 15 分钟内的官方历史结果，并标记状态
- 监视本机 Codex 会话，按会话展示最新轮次，支持静音、移除和恢复监视
- 桌面与飞书通知独立开关，通知包含会话标题、结束状态和本轮需求摘要
- 飞书支持 Webhook 签名、配置加密保存、@所有人、测试通知和发送结果展示
- 日志变化后约 50 毫秒调度增量读取，优先处理已知变化，并保留定期扫描兜底

## 使用方式

从 [GitHub Releases](https://github.com/Lele-bigLe/codex-status-line/releases) 下载对应操作系统的安装包，安装并启动应用。

- 默认以托盘模式运行，点击托盘图标打开详情；可在设置中切换为悬浮状态条
- 悬浮模式下，点击托盘图标显示或隐藏悬浮窗；点击悬浮条可刷新额度
- 从详情面板进入设置或任务窗口，也可使用托盘菜单
- 任务窗口支持自动展开、收起和固定展开；每个会话只展示最新轮次

### 任务与桌面通知

1. 在设置中开启「本机任务监视」。
2. 按需开启「桌面完成通知」和「桌面通知声音」，并允许操作系统显示通知。
3. 在 Codex 中发起新轮次；本轮结束或中断后会显示通知。

任务监视读取 `CODEX_HOME/sessions` 中的本机会话 JSONL，未设置 `CODEX_HOME` 时使用默认 Codex 目录。会话标题来自 `session_index.jsonl`，需求摘要从本轮用户消息中提取；子代理不单独提醒。

- 「本轮结束」表示收到了结束事件，不用于判断任务结果是否成功。
- 首次启动、重启应用或重新启用监视时，不补发历史结束通知。
- 会话静音会同时停止桌面和飞书提醒；移除仅停止该会话的显示和通知，不会终止 Codex。
- 恢复会话后只提醒新事件；监视中断的运行任务会显示「状态未知」，等待新日志更新。
- 50 毫秒是文件监听触发后的读取调度间隔，不是通知送达承诺；实际延迟还包括日志写入、文件读取和系统通知展示。

### 飞书手机通知

iPhone 和安卓均使用手机飞书接收群消息。**电脑端飞书无需登录，也无需运行**；电脑上的 codex-status 需保持运行、联网并开启任务监视。

1. 在飞书中创建专用通知群，例如「Codex 通知」，个人使用可建立只有自己的群。
2. 打开群设置 → 群机器人 → 添加机器人 → 自定义机器人，保存 Webhook 地址。
3. 建议在机器人安全设置中开启「签名校验」，保存签名密钥。
4. 打开 codex-status 设置 →「飞书手机通知」，填写地址和密钥，开启「轮次结束时推送」。
5. 只有自己的通知群可开启「通知时 @所有人」，无需获取个人用户 ID；在飞书群管理中确保允许机器人 @所有人，然后点击「保存配置」。不需要 @ 提醒时保持关闭即可。
6. 点击「发送测试通知」，确认手机能收到；开启 @所有人时还应检查群消息是否出现有效的 @所有人，再保持任务监视开启以接收后续轮次提醒。

配置说明：

- 支持飞书国内版群机器人地址：`https://open.feishu.cn/open-apis/bot/v2/hook/…`。
- 机器人开启签名校验时必须填写密钥；未启用时可以留空。若同时配置了关键词或 IP 白名单，请确保通知与网络出口满足对应规则；消息会带有 `Codex Status` 前缀。
- 常规设置自动保存，飞书配置需单独点击保存；有未保存修改时不能发送测试通知。
- 「通知时 @所有人」默认关闭，旧配置升级后也保持关闭；开启并保存后，轮次通知和测试通知都会 @群内所有成员。多人群开启前请确认这符合群的用途。
- 开启飞书通知后，会将会话标题、结束状态及需求摘要发送到指定群；请使用适合接收这些内容的群。
- Webhook 和密钥由系统安全存储能力加密后保存在本机，不写入普通设置文件。不要公开分享这两项凭据；系统加密能力不可用时会拒绝保存。
- 「飞书已接收」表示接口确认接收，不代表手机已经弹出提醒；发送失败会显示原因。最近发送结果保留在本次应用运行期间，重新保存配置后重置。
- 发送使用系统代理/PAC，单次请求超时为 10 秒；串行发送间隔至少 1 秒，明确遇到限流时最多重试一次。网络超时可能已经送达，因此不会自动重发。

手机端请开启飞书的系统通知权限，并关闭通知群的免打扰。若电脑或 iPad 同时登录飞书，检查手机飞书设置，不要启用「桌面端在线时关闭手机通知」。iPhone 还需允许锁定屏幕、横幅和声音提醒。

参考：[飞书自定义机器人指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)、[飞书消息通知设置](https://www.feishu.cn/hc/zh-CN/articles/111093338362-设置消息通知)。

### 飞书会话交互（测试阶段）

此入口使用**飞书自建应用机器人**，与上面的 Webhook 状态通知机器人独立。默认仅验证会话定位；开启「Codex 执行」后，可以继续一个指定的已有测试会话，接收 AI 回答并回应追问。目前不创建新会话。

1. 在飞书开放平台创建自建应用，启用机器人能力，取得 App ID 和 App Secret。
2. 开通接收群内 @机器人消息（`im:message.group_at_msg:readonly`）和以应用身份发送消息（`im:message:send_as_bot`）权限，订阅接收消息事件 `im.message.receive_v1`，选择长连接方式。配置发布后，将机器人加入测试群。
3. 在「设置 → 消息接收」填写应用凭据、允许的群 ID（`oc_…`）和该应用下用户的 Open ID（`ou_…`）。开启接收并保存；配置长连接订阅时如需先建立连接，可先保存应用配置，再完成事件订阅。界面显示“连接成功”只代表连接建立，收到消息和回执会分别显示时间。
4. 在「事件与回调 → 回调配置」中另选长连接，添加「卡片回传交互」`card.action.trigger`，保存并发布。消息事件和卡片回调需要分别配置。
5. 开启本机任务监视。在指定群中由允许的用户 **@机器人** 发送 `项目列表`，点击项目旁的「选择」，卡片自动显示该项目的会话，再点击会话旁的「选择」。底部提供「切换项目」「切换会话」「当前会话」按钮，无需逐条输入命令。按钮只允许配置的用户在配置的群内操作。
6. 选定后直接 **@机器人** 发送任意文字，确认回执中的项目路径和会话 ID；无需引用旧消息。也可回复带会话绑定的旧回执并 @机器人，验证指定会话定位。文字命令仍支持 `选择项目 1`、`会话列表`、`选择会话 1`；选择项目后会自动显示会话列表。

真实对话：在同一设置页填写「允许执行的测试会话 ID」，启用「在测试会话中启用真实执行」并保存。只会向这个 ID 提交需求，其他会话继续只支持定位。Codex 可执行文件路径留空时从 PATH 查找 CLI，也可填写兼容的原生可执行文件完整路径（Windows 使用 `codex.exe`）。独立 CLI 与桌面应用自带的 Codex 可能支持不同会话格式；如果提示不支持会话格式，应选用能恢复该会话的程序，不能仅凭版本号判断兼容性。

- 使用本机 Codex 登录，通过 App Server 的 stdio 接口恢复会话并启动轮次；每轮结束后释放该进程，下一轮重新恢复磁盘上下文。
- 首版采用只读沙箱与 `untrusted` 审批策略，审批由用户处理；模型进展和回答由会话机器人返回，长回答分段发送，不发送内部推理或工具原始日志。
- 普通追问直接 @机器人回答即可。结构化问题提供选项按钮，也可回复问题卡片并 @机器人输入答案；多个同时待答的问题必须回复对应卡片。问题、审批和停止按钮绑定当前请求，过期操作不能作用于新轮次。
- 命令审批展示完整命令、目录与原因，只提供本次允许/拒绝；文件写入授权、额外权限、网络专门审批、敏感输入和其他未支持的交互不会自动批准，会提示回电脑处理并请求中断。
- 会话已在其他窗口运行或状态未知时拒绝启动；首版不要在桌面/CLI 与飞书中同时执行同一测试会话。处理中可点击“停止本轮”。保存飞书配置或退出应用会断开当前执行进程，已发出的工具操作需在电脑上检查结果。
- 出错、连接中断或请求超时时不自动重提需求，避免重复执行。配置和真实会话 ID 仅保存在本机加密配置中。

项目和会话来自当前任务监视中可见的记录，不代表本机全部历史会话。列表每次最多显示 30 项；编号绑定到当次列表，不随后台排序变化。只接受指定群、指定用户 @当前机器人的消息；暂不接收私聊和非文字输入。

选择、卡片菜单和消息绑定保存在本次接收连接的内存中（各最多保留 1000 条菜单及回执绑定），重启应用或重新保存飞书配置会清空。旧卡片过期后，需重新 @机器人发送“项目列表”。按钮绑定具体项目路径或会话 ID，不随后续列表排序改变。旧 Webhook 通知、无绑定的引用消息、已移除会话不会回退到其他会话。界面中的保存按钮同时保存飞书通知和消息接收配置；应用凭据仍经系统安全存储加密。

接收使用飞书官方 Node SDK 长连接，无需公网回调服务器。电脑需运行并联网；SDK 网络连接与原 Webhook 通知的 Electron 网络栈不同，不承诺沿用系统 PAC。接收前的积压消息会忽略，重复事件会去重；回执未确认送达时显示错误，不自动重发。

本地逻辑测试：`node --test scripts/feishu-routing.test.mjs scripts/codex-session.test.mjs`。测试包含模拟消息传输和 App Server 协议；真实群收发仍需使用上述配置联调。

参考：[飞书官方 Node SDK](https://github.com/larksuite/node-sdk)、[接收消息事件](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)。

## 数据来源

额度信息按以下顺序读取：

1. 官方接口：`https://chatgpt.com/backend-api/wham/usage`
2. 同一账号的官方成功结果：仅保存在内存中，最长回退 15 分钟

会话 JSONL 仅用于任务监视，不用于额度回退，因为它无法可靠确认账号归属。切换账号或退出登录会清空旧额度结果，同账号续期保留此前已确认的数据并重新同步；重置时间到达后等待官方确认，不自动推算为满额。

## 使用前提

- 若要读取官方额度，当前环境需要存在 `~/.codex/auth.json`
- `auth.json` 需要处于 ChatGPT OAuth 模式，并包含可用的 `access_token`
- 需要能够识别账号标识；面板显示脱敏账号、工作区和实际凭据路径（遵循 `CODEX_HOME`）
- 凭据不可用时显示连接原因；自动模式继续检查登录状态，手动模式可点击刷新重试
- 任务监视需要可读取的本机会话日志；飞书推送还需要有效的群机器人 Webhook 和网络连接

## 本地开发

### 额度请求的网络连接

- 额度请求使用 Electron 网络栈，支持系统代理和 PAC。仅浏览器插件中的代理不一定对应用生效。
- 每次请求最多等待 20 秒（包括响应体读取）；临时网络故障或部分服务端错误等待 1 秒后最多重试一次，重试前重新核对登录账号和凭据。
- 登录失效、权限拒绝、限流及证书错误不立即重试；服务端要求延后重试时也不立即重发。失败原因可在详情的“连接信息”中查看。

## 状态持久化

应用将数据保存到 Electron `userData` 目录：

| 文件 | 内容 |
| --- | --- |
| `codex-status-state.json` | 常规设置与窗口位置 |
| `codex-status-tasks.json` | 任务记录、会话静音及移除状态 |
| `codex-status-feishu.bin` | 经系统加密的飞书配置，包含 Webhook 与签名密钥 |

飞书配置依赖当前系统账户的加密能力，复制到另一台电脑或账户后可能无法解密，需要重新配置。

## 发布

GitHub Actions 的 `Release` 工作流由 `v*` 标签推送或手动运行触发。标签必须与 `package.json` 中的版本一致，同时保持 `package-lock.json` 顶层及根包版本同步。

工作流会分别在 Windows、macOS 和 Linux 上安装依赖、执行构建并打包，全部完成后发布 GitHub Release。推送标签已触发时无需再次手动运行。
