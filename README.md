# codex-status

一个基于 Electron、React 和 TypeScript 的 Codex 额度与任务状态工具。

通过系统托盘、悬浮胶囊和任务窗口查看额度与本机任务进度。Codex 轮次结束或中断后，可发送桌面或飞书通知；也可在手机飞书中选择项目、继续会话并处理审批。

## 友情社区

- [linux.do](https://linux.do/)

## 功能概览

- 悬浮胶囊窗口，常驻桌面顶层显示实际额度窗口，支持直接打开详情
- 支持剩余百分比 / 已使用百分比两种口径切换
- 官方 OAuth 可用时支持自动刷新和手动刷新
- 支持中英文界面
- 支持系统托盘菜单：显示/隐藏、刷新、设置、退出
- 读取官方额度接口，失败时仅展示同一账号最近 15 分钟内的官方历史结果，并标记状态
- 监视本机 Codex 会话，按会话展示最新轮次，支持静音、移除和恢复监视
- 桌面与飞书通知独立开关，飞书结束通知包含本轮需求和最终回答，长回答显示预览
- 飞书应用机器人支持私聊、多项目会话切换、逐会话授权与审批
- 飞书支持 Webhook 签名、配置加密保存、@所有人、测试通知和发送结果展示
- 日志变化后约 50 毫秒调度增量读取，优先处理已知变化，并保留定期扫描兜底

## 使用方式

从 [GitHub Releases](https://github.com/Lele-bigLe/codex-status-line/releases) 下载对应操作系统的安装包，安装并启动应用。

- 默认以托盘模式运行，点击托盘图标打开详情；可在设置中切换为悬浮状态条
- 悬浮模式下，点击托盘图标显示或隐藏悬浮窗；点击悬浮条可刷新额度
- 从详情面板进入设置或任务窗口，也可使用托盘菜单
- 任务窗口支持自动展开、收起和固定展开；每个会话只展示最新轮次

### 任务与桌面通知

1. 在设置中开启「本机任务监视」。
2. 按需开启「桌面完成通知」和「桌面通知声音」，并允许操作系统显示通知。
3. 在 Codex 中发起新轮次；本轮结束或中断后会显示通知。

任务监视读取 `CODEX_HOME/sessions` 中的本机会话 JSONL，未设置 `CODEX_HOME` 时使用默认 Codex 目录。会话标题来自 `session_index.jsonl`，需求摘要从本轮用户消息中提取；子代理不单独提醒。

- 「本轮结束」表示收到了结束事件，不用于判断任务结果是否成功。
- 首次启动、重启应用或重新启用监视时，不补发历史结束通知。
- 会话静音会同时停止桌面和飞书提醒；移除仅停止该会话的显示和通知，不会终止 Codex。
- 恢复会话后只提醒新事件；监视中断的运行任务会显示「状态未知」，等待新日志更新。
- 50 毫秒是文件监听触发后的读取调度间隔，不是通知送达承诺；实际延迟还包括日志写入、文件读取和系统通知展示。

### 飞书机器人协作（推荐私聊）

使用**企业自建应用机器人**，在同一个机器人中接收完成通知、切换项目、继续 Codex 会话和处理审批。私聊无需 @；群聊需要 @机器人。电脑上的 Codex Status 需保持运行、联网并开启任务监视，电脑端飞书无需登录或运行。

#### 1. 准备并连接机器人

1. 在[飞书开发者后台](https://open.feishu.cn/app)创建企业自建应用，添加“机器人”能力，在“凭证与基础信息”获取 App ID 和 App Secret。
2. 开通以下**应用身份**权限：私聊需要 `im:message.p2p_msg:readonly` 和 `im:message:send_as_bot`；群聊将接收权限换成 `im:message.group_at_msg:readonly`。
3. 按[获取 Open ID 指南](https://open.feishu.cn/document/faq/trouble-shooting/how-to-obtain-openid)，在 API 调试台选择当前应用并复制自己的 `ou_…` ID。同一个人在不同应用下的 Open ID 不同，不能混用。
4. 打开 Codex Status「设置 → 机器人协作」，启用机器人，选择“私聊”，填写应用凭据和允许的用户 Open ID。群聊还需填写允许的群 ID（`oc_…`）。
5. 需要继续 Codex 任务时，勾选“允许从飞书执行 Codex 任务”，然后点击“保存并连接”。该开关不会自动授权任何会话。

#### 2. 订阅事件并发布

1. 保持 Codex Status 运行，等待界面显示“长连接已建立”。后台提示未建立长连接时，先完成上一步的本机保存与连接。
2. 在“事件与回调 → 事件配置”选择长连接，添加“接收消息” `im.message.receive_v1`。
3. 在“回调配置”另选长连接，添加“卡片回传交互” `card.action.trigger`；否则下拉框、授权和审批按钮无法响应。
4. 在“版本管理与发布”中创建版本，将自己加入可用范围并发布；如需管理员审核，等待通过。修改权限、事件或回调后也需发布，群聊模式还需将机器人加入配置的群。

“长连接已建立”只表示本机连接成功，不能据此判断权限、事件和应用发布均已完成。最近接收、回执时间用于核对真实消息链路。

#### 3. 在手机开始使用

1. 在「设置 → 任务通知」开启本机任务监视。先确认电脑 Codex 可正常对话，在目标项目发起一次对话，等待任务监视发现该项目与会话。
2. 在手机飞书搜索应用名称，进入机器人私聊，发送 `项目列表`；群聊则 @机器人发送该命令。
3. 使用下拉框选择项目、会话。开启并保存执行开关后，“新建会话”可在已选项目中另开会话。切回项目会恢复上次仍可见的会话；不会自动改选其他会话。
4. 在会话“详情”中授予只读或项目写入权限，再发送需求。私聊直接发送文字；群聊继续 @机器人。也可在桌面“会话授权与程序设置”中管理授权或指定 Codex 程序路径。

项目来自任务监视中的可见记录，每次最多显示 30 个项目及 30 个会话。若没有目标项目，请先在电脑 Codex 中打开该项目并发起对话；手机不能直接导入任意目录。

使用说明：

- 各会话的上下文、消息、审批与停止操作分别绑定；同一项目的文件仍共用，不要在多个客户端同时执行同一会话。
- 普通回答复用原卡，长文默认预览，结束后可展开、收起或在原卡翻页。问题和审批另卡完整展示；多个待答问题须回复对应的问题卡片。
- 项目写入仅限会话项目内文件；命令和文件审批展示完整命令或差异，超出项目范围及其他不支持的权限需回电脑处理。
- 在“飞书通知”开启“轮次结束时推送”，电脑任务的结束提醒会附需求与最终回答；长回答节选并标记预览。飞书对话已有回答卡的轮次不再重复推送。
- 保存飞书配置会重新连接机器人并断开当前飞书执行连接，请等进行中的任务结束再保存。关闭机器人并保存，会同时暂停执行与飞书完成通知。
- 新建空会话后，请保持连接，在卡片中授权并发送首条需求；首条需求前重启应用或重新保存飞书配置，会关闭该空会话的创建连接，需重新新建。
- 项目最近会话记忆、应用凭据及会话授权加密保存在本机。重启或重新保存配置后，发送 `项目列表` 获取新菜单；旧卡片按钮和旧消息绑定会过期，同一应用、用户和聊天下的项目记忆仍可恢复。
- 接收使用官方 Node SDK 长连接，无需公网回调服务器。连接中断、超时或回执未确认时不会自动重提需求；请先核对电脑端结果。

参考：[接收消息事件](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)、[卡片回调配置](https://open.feishu.cn/document/event-subscription-guide/callback-subscription/receive-and-handle-callbacks)、[官方 Node SDK](https://github.com/larksuite/node-sdk)。

### 仅接收群通知（Webhook）

未启用协作机器人时，可使用自定义群机器人的 Webhook，仅接收完成通知。启用协作机器人后，通知统一通过应用机器人发送，不同时发送 Webhook。

1. 在飞书群设置中添加自定义机器人，取得 Webhook；若开启签名校验，同时取得签名密钥。
2. 在「设置 → 飞书通知」填写 Webhook 和密钥，开启“轮次结束时推送”并保存。
3. 点击“发送测试通知”。若需要 @所有人，请先确认群允许机器人这样做；测试消息也会 @所有人。

飞书配置需单独保存，未保存时不能发送测试通知。凭据由系统安全存储加密，不要公开分享。“飞书已接收”只表示接口确认，不代表手机已经弹出提醒；超时可能已经送达，不会自动重发。

手机端请开启飞书的系统通知权限并关闭会话免打扰；若其他设备也在线，请检查“桌面端在线时关闭手机通知”等选项。

参考：[自定义机器人指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)、[飞书消息通知设置](https://www.feishu.cn/hc/zh-CN/articles/111093338362-设置消息通知)。

「检查程序与协议」只启动程序并验证 App Server 初始化，展示实际路径和版本，不恢复会话或提交需求。执行时另验证会话是否可恢复、ID 和工作目录是否一致；自动模式可在恢复失败且尚未提交需求时换用其他候选。一旦调用 `turn/start`，即使超时或返回错误也不换程序重试，避免重复执行。未来版本仍可能需要协议适配，不能仅凭版本号保证兼容。

- 使用本机 Codex 登录，通过 App Server 的 stdio 接口恢复会话并启动轮次；每轮结束后释放该进程，下一轮重新恢复磁盘上下文。
- 每个会话使用各自的沙箱权限与独立执行连接，可切换会话或同时等待不同会话的问题，不会把回答交给其他会话。新增授权默认只读；项目写入模式的可写目录限定为会话工作目录，禁用临时目录额外写入和直接网络访问。两种模式均采用 `untrusted` 审批策略，审批由用户处理。
- 模型进展和回答由会话机器人返回，不发送内部推理或工具原始日志。问题、审批和停止按钮绑定当前请求，过期操作不能作用于新轮次。
- 命令审批展示完整命令、目录与原因，只提供本次允许/拒绝。项目写入模式支持文件审批：展示完整差异，只接受项目内路径（包括重命名目标），缺少差异、超过可展示长度、符号链接指向项目外或请求额外授权根目录时拒绝。只读模式不接受文件写入审批；额外权限、网络专门审批、敏感输入和其他未支持的交互仍需回电脑处理。
- 会话已在其他窗口运行或状态未知时拒绝启动；不要在桌面/CLI 与飞书中同时执行同一会话。处理中可点击“停止本轮”。保存飞书配置或退出应用会断开当前执行进程，已发出的工具操作需在电脑上检查结果。
- 仅接收配置用户的文字消息；群模式还限定配置的群。旧通知、无绑定的引用消息、已移除会话不会回退到其他会话。

接收使用飞书官方 Node SDK 长连接，无需公网回调服务器。电脑需运行并联网；SDK 网络连接与原 Webhook 通知的 Electron 网络栈不同，不承诺沿用系统 PAC。接收前的积压消息会忽略，重复事件会去重；回执未确认送达时显示错误，不自动重发。

本地逻辑测试：`node --test scripts/feishu-routing.test.mjs scripts/codex-session.test.mjs`。测试包含模拟消息传输和 App Server 协议；真实群收发仍需使用上述配置联调。

参考：[飞书官方 Node SDK](https://github.com/larksuite/node-sdk)、[接收消息事件](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)。

## 数据来源

额度信息按以下顺序读取：

1. 官方接口：`https://chatgpt.com/backend-api/wham/usage`
2. 同一账号的官方成功结果：仅保存在内存中，最长回退 15 分钟

会话 JSONL 仅用于任务监视，不用于额度回退，因为它无法可靠确认账号归属。切换账号或退出登录会清空旧额度结果，同账号续期保留此前已确认的数据并重新同步；重置时间到达后等待官方确认，不自动推算为满额。

## 使用前提

- 若要读取官方额度，当前环境需要存在 `~/.codex/auth.json`
- `auth.json` 需要处于 ChatGPT OAuth 模式，并包含可用的 `access_token`
- 需要能够识别账号标识；面板显示脱敏账号、工作区和实际凭据路径（遵循 `CODEX_HOME`）
- 凭据不可用时显示连接原因；自动模式继续检查登录状态，手动模式可点击刷新重试
- 任务监视需要可读取的本机会话日志；飞书功能还需有效的应用机器人配置或群机器人 Webhook，以及网络连接

## 本地开发

### 额度请求的网络连接

- 额度请求使用 Electron 网络栈，支持系统代理和 PAC。仅浏览器插件中的代理不一定对应用生效。
- 每次请求最多等待 20 秒（包括响应体读取）；临时网络故障或部分服务端错误等待 1 秒后最多重试一次，重试前重新核对登录账号和凭据。
- 登录失效、权限拒绝、限流及证书错误不立即重试；服务端要求延后重试时也不立即重发。失败原因可在详情的“连接信息”中查看。

## 状态持久化

应用将数据保存到 Electron `userData` 目录：

| 文件 | 内容 |
| --- | --- |
| `codex-status-state.json` | 常规设置与窗口位置 |
| `codex-status-tasks.json` | 任务记录、会话静音及移除状态 |
| `codex-status-feishu.bin` | 经系统加密的飞书凭据、会话授权及项目最近会话记忆 |

飞书配置依赖当前系统账户的加密能力，复制到另一台电脑或账户后可能无法解密，需要重新配置。

## 发布

GitHub Actions 的 `Release` 工作流由 `v*` 标签推送或手动运行触发。标签必须与 `package.json` 中的版本一致，同时保持 `package-lock.json` 顶层及根包版本同步。

工作流会分别在 Windows、macOS 和 Linux 上安装依赖、执行构建并打包，全部完成后发布 GitHub Release。推送标签已触发时无需再次手动运行。
